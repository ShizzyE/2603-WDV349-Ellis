# OpenAI in PlanBuddy 🤖 → 🖥️

OpenAI offers an Agent SDK that fits well with how I want to use AI inside of PlanBuddy. Instead of having the AI only respond to prompts, I want the agent to act more like a personal assistant for each user. Agents can be configured with instructions, models, tools, and handoffs to other agents. This would allow PlanBuddy's AI to access information such as a user's tasks, priorities, overdue tasks, calendar, and notes and use that information to give more useful responses and take actions when needed.

For conversation state, OpenAI provides four common strategies: `session`, `conversationId`, `previous_response_id`, and `result.to_input_list()`. I plan to use the **session** strategy for PlanBuddy because it allows the application to maintain persistent chat state and reuse the same session for future conversations. This is important because I want the AI assistant to remember the conversation instead of treating every message as a completely new request. The user's actual tasks and other productivity data will still be stored in the PlanBuddy database, while the session will handle the conversation history.

Another important part of using an AI agent is **guardrails and human review**. Guardrails can automatically check user input, AI output, and tool actions before they are completed. Human review can also be used when the AI wants to perform a more sensitive action. For PlanBuddy, this could be useful for actions such as deleting a task or making a major change to a user's schedule. These controls can help make sure the AI only accesses and changes the correct user's information.

OpenAI also provides **tracing and evaluation tools** that can help me understand how the agent is working. Tracing can show the model calls, tool calls, guardrails, and other steps that happen during an agent run. This would help me debug PlanBuddy if the AI chooses the wrong tool or gives an incorrect response. Evaluation tools can then be used to test common situations, such as identifying overdue tasks, choosing the correct priority, or helping a user decide what they should work on next.

Overall, I want PlanBuddy's AI to be more than a simple prompt box. The goal is to create an assistant that understands the user's productivity data and can help manage it. OpenAI's Agent SDK, sessions, tools, guardrails, tracing, and evaluation features provide the foundation for building that type of assistant while still allowing PlanBuddy to control its own database and application logic.
