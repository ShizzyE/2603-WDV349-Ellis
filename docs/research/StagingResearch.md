# What is Staging in Software Development?
Staging, or more commonly referred to as a staging environment in software development, is a test system that looks and functions just like a live production app. It provides developers with a safe environment to test new features, fixes, and updates before they are released to production. This helps identify bugs, security issues, and other problems without affecting the live application or its users. For PlanBuddy, the staging environment allows me to thoroughly test changes before merging them into the main production branch.


## Clean Code 👨🏽‍💻

Writing clean code is an on going process from beginning to the end of a coding project. It's harder to clean up finished messy and sloppy code than it is to just clean and maintain the code during development. Although I am not a professional yet, it is important to build healthy habits of cleaning code and not rushing the development process because of deadlines. For PlanBuddy, a limited clean coded functional app is better than a working vulnerable slop of code rushed together. 


## Organizing CSS 🗄️🖼️

Organizing CSS can be done in multiple different ways. One of the most important things is keeping the code consistent and easy to read. This can include using consistent naming conventions, formatting properties on separate lines, and separating styles into logical sections. For larger projects, CSS can also be broken into smaller files or organized around specific components instead of putting everything into one large stylesheet. This makes it easier to find specific styles, make changes, and avoid accidentally affecting other parts of the application. Another important practice is avoiding overly specific selectors and reusing styles when possible. Overall, properly organizing CSS helps keep a project maintainable as it continues to grow.


## 80/20 Rule 🕙

The Pareto Principle, also known as the 80/20 rule, is a way of looking at what tasks or problems are actually creating the biggest impact. Instead of trying to treat every task like it has the same importance, the goal is to identify the smaller number of tasks that will produce the most results. This can be useful when working on a large project because there will always be a lot to do, but not everything needs the same level of attention at the same time. For PlanBuddy, I think this principle can be useful for prioritizing which features, bugs, and improvements should be worked on first. The goal is not to ignore the other 80% of tasks, but to understand what should be focused on first so that time is not being wasted on things with little impact.


## Importance of Code Comments 💬

Code comments are useful when they provide information that cannot easily be understood from the code itself. I think comments should mainly explain why something was done instead of explaining what the code is already doing. Comments can be helpful for things like unusual solutions, important warnings, business logic, or decisions that another developer might question later. At the same time, adding comments everywhere can make the code more cluttered and harder to maintain, especially if the comments become outdated when the code changes. I also think this is important when using AI coding tools because they can add unnecessary comments that simply repeat what the code says. For PlanBuddy, I want to focus on making the code readable on its own and only adding comments when they provide useful context that would not be obvious from the code.

## ReadMe Importance 📋

A good README is important because it gives people a better understanding of what a project is and how it works without having to look through all of the code. A README should explain things like the purpose of the project, technologies used, how to launch it, and the main features. Even though PlanBuddy is still a learning project, having good documentation is important because I may need to come back to the project later and understand what I was doing. It also makes the project easier for other developers or recruiters to understand when looking at my GitHub. For PlanBuddy, I think keeping the README clear and simple is better than trying to fill it with unnecessary information. It should explain what PlanBuddy does, how the frontend, backend, database, and AI work together, and how someone can get the project running without having to dig through the code.
